# RVVMF — Accuracy & Performance Benchmarks

> **Snapshot Date:** November 14, 2026 (presented at the [VIII Russian RISC-V Alliance Meetup](https://riscv-alliance.ru/meetup/vosmoj-mitap-alyansa-risc-v)).

This document summarizes the numerical accuracy verification and performance benchmarking (in Cycles Per Element, **CPE**) of **RVVMF** compared against established scalar and vector mathematical libraries on RISC-V RVV 1.0 hardware.

---

## 1. Test Environment & Competing Libraries

### Hardware & Software Setup
* **Board:** Banana Pi BPI-SM10
* **SoC:** SpacemiT K3
  * **Performance Cluster:** 8x **X100** Out-of-Order cores (`RV64GCV`, RVA23 profile, RVV 1.0, $\text{VLEN} = 256\text{ bits}$) — *used for primary throughput benchmarks*.
  * **Efficiency Cluster:** 8x **A100** In-Order cores (`RV64GCV`, RVA22 profile, RVV 1.0, $\text{VLEN} = 1024\text{ bits}$).
* **Memory:** 8 GB LPDDR5
* **OS:** Bianbu 4.0.1
* **Compiler:** Clang 21 (Cross-compilation)

### Evaluated Libraries
1. **RVVMF:** Pure RVV 1.0 intrinsic implementation (`fp64`, `fp32`, `fp16`), fully Vector-Length Agnostic (VLA) across all `LMUL` settings.
2. **SLEEF:** Cross-platform SIMD library translated via generalized pseudo-intrinsics (supports RVV only for $\text{LMUL} = 1, 2$).
3. **veclibm (RIVOS):** RVV intrinsic-based vector library (supports `fp64` only, array-based interface with fixed $\text{LMUL}$).
4. **libm:** Standard scalar math library.

## 2. Numerical Accuracy Verification

RVVMF is evaluated against two strict criteria:
1. **Statistical Accuracy ($\le 0.501\text{ ULP}$):** Faithful rounding where at most $1$ out of $1,000$ random floating-point inputs deviates from $0.5\text{ ULP}$.
2. **Maximum Observed Error (ISO/IEC 10967-2 Compliance):** Basic elementary functions must stay within $\le 0.75\text{ ULP}$, and composite/additional functions within $\le 1.5\text{ ULP}$.
